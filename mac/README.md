# SmartClip for Mac

A menu-bar companion to SmartClip's `/cpy`, `/pst` and `/clh` commands. It
records **everything you copy**, not just what Claude copies for you, into the
same history store — so `/pst` and `/clh` can reach your own clips too — and
gives you a ⌥⌘V picker to paste any of them back.

```bash
cd mac
./scripts/build-app.sh --install --run
```

Then, in the menu bar icon: **Open at login**, and **Enable paste-back…** to
grant Accessibility (needed only for pressing ⌘V for you — everything else
works without it).

## Using it

| Key | What happens |
|---|---|
| `⌥⌘V` | open the picker |
| type | filter by content, source app or type |
| `↑` `↓` | move through the list |
| `⏎` | paste into the app you came from |
| `⌘1`–`⌘9` | paste that item straight away |
| `⎋` | close |

The menu bar icon also lists the last 8 clips (click to put one on the
clipboard), pauses capture, and opens the history folder.

## How it fits with the Claude Code commands

Everything shares one store at `~/.local/share/smartclip`:

- `/cpy` writes a **labelled** entry ("reply to Sam") through `bin/smartclip`.
  The app sees that same clipboard change, waits, notices the helper already
  logged it, and stays out of the way.
- The app writes entries for every other copy, tagged with the **source app**.
- `/clh` and `/pst` read the whole lot, so "the link I copied from Slack" is
  something Claude can actually resolve.

The picker labels each clip with where it came from — an app name, or "Claude"
for the ones `/cpy` made.

## Privacy

The same rules as the CLI, enforced in the app:

- Anything carrying the `org.nspasteboard.ConcealedType`, `TransientType` or
  `AutoGeneratedType` marker is skipped. That is the convention password
  managers use, so 1Password copies are never recorded.
- 1Password, Bitwarden, Keychain Access and friends are also skipped by bundle
  id, in case an app forgets the marker.
- Content that looks like a credential (tokens, keys, JWTs, `password=…`) is
  logged as `redacted` with the content **not** written to disk.
- Clips over 1 MiB are noted but not stored.
- Everything lives in `~/.local/share/smartclip` as plaintext, owner-only
  (`700`/`600`), capped at 1000 entries. `smartclip history clear` wipes it.
- Nothing leaves the machine.

Set `SMARTCLIP_HISTORY_EXCLUDE='<regex>'` to add your own never-store patterns.

## Notes for working on it

Things that are not obvious about clipboard apps on macOS:

- **There is no clipboard-changed notification.** `ClipboardWatcher` polls
  `NSPasteboard.general.changeCount` twice a second — an integer compare, which
  is what every clipboard manager does.
- **Reading the clipboard in the background does not prompt** on macOS 26 (26.0
  verified). If a future release adds the prompt, the app will need "Paste from
  other apps: Always Allow" in System Settings.
- **Accessibility permission is tied to the code signature**, so
  `build-app.sh` signs every build with the same Apple Development identity.
  An ad-hoc signature changes each build and macOS would revoke the grant.
- **The hotkey uses Carbon's `RegisterEventHotKey`**, the one API that gives a
  system-wide hotkey *without* Accessibility. An event tap would need the grant
  just to listen for the keystroke.
- **The helper copies first and logs second**, so the app waits 0.6 s before
  recording a clip and then checks whether `/cpy` already logged it. Without
  that wait you get every Claude copy twice.

```bash
swift test                          # core: store format, secret filter, pruning
SMARTCLIP_DEBUG=1 .build/debug/SmartClipMac   # trace what it is doing
SmartClip --show                    # open the picker from a script or a test
```
